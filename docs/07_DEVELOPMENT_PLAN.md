# Jungle JIM — 개발 단계·MVP·수용 조건

> 버전 1.0 · 상태: 실행 전 계획 · 코드·빌드·테스트가 완료됐다는 보고가 아님
> 전체 문서의 진입점: [01_GAME_OVERVIEW.md](01_GAME_OVERVIEW.md)

## 1. 개발 원칙과 범위

먼저 CH01 하나를 시작부터 끝까지 작동시키고, 그 기반으로 5챕터를 확장한다. 이야기의 완성 범위와 첫 납품 범위를 분리한다. MVP에 Mother Core·자유 분대 AI·제작 시스템을 넣지 않는다.

- **P0:** MVP 진행에 필수. 이동·사격·Stalker·목표·보급·저장·CH01.
- **P1:** 5챕터 캠페인에 필수. 추가 무기·적·보스·서사·엔딩·에셋·접근성.
- **P2:** 이후 검토. 추가 난도·컨트롤러·사진 모드·고급 그래픽. 출시 약속이 아니다.
- **명시적 제외:** 멀티플레이, 오픈월드, 생존 제작·기지, 절차 생성, 자유 차량, 실제 학습 AI, 분기 엔딩, 후속편 구현.

## 2. 구현 전 조사: 기존 프로젝트를 먼저 읽는다

### TASK-00 / 프로젝트 현황표

확인: 엔진·버전, 실행 진입점, 빌드 명령, 플레이어·카메라·입력, 무기·적·레벨, 저장, 리소스 경로, 테스트, 라이선스. 저장소의 작업 지침이 있으면 읽고 따른다.

결과: ‘재사용 / 수정 / 신규’ 표와 실행 가능한 기준 상태. 기능이 이미 있으면 중복 시스템을 만들지 않는다. 문서에 없는 기술 선택은 엔진 제약·이유·대안을 짧게 기록한다.

**수용 조건:** 팀이 같은 방법으로 현재 프로젝트를 실행할 수 있다. 엔진 미확정 상태에서 대규모 폴더·코드 생성을 시작하지 않는다. 원본 게임을 삭제하거나 무단으로 다른 엔진으로 갈아엎지 않는다.

## 3. 시스템 책임 분리 제안

이름은 설명용이며 실제 언어·엔진에 맞춘다. 클래스 이름 자체를 완료 조건으로 삼지 않는다.

| 책임 | 입력 | 출력·소유 상태 |
|---|---|---|
| PlayerController | 액션 입력 | 이동·행동 요청, 조작 잠금 |
| CameraRig | 플레이어·조준 상태 | 카메라 위치·충돌·시야각 |
| WeaponSystem | 발사·재장전 요청 | 탄약, 명중 요청, VFX 이벤트 |
| DamageService | 공격·부위·방어 상태 | 실제 피해·사망, 중복 방지 |
| EnemyBrain | 감지·전투 상태 | 이동·예고·공격·후딜 |
| MissionDirector | 안정 ID를 가진 게임 이벤트 | 목표 상태·전환·출구 잠금 |
| EncounterDirector | 전투 시작·처치 | 웨이브·동시 활성 상한 |
| Dialogue/Cutscene | 장면 요청 | 자막·입력 잠금·완료 이벤트 |
| SaveService | 체크포인트·스냅샷 | 버전 저장·로드·오류 처리 |
| UI Presenter | 위 시스템의 읽기 상태 | HUD·메뉴, 게임 상태 직접 변경 금지 |

체력·탄약·목표의 진실을 UI와 월드 오브젝트가 각각 중복 보유하지 않는다. 장면 스크립트가 임의로 체력을 깎는 대신 공통 피해 경로를 사용한다.

이벤트 예: `WeaponAcquired`, `DamageApplied`, `EnemyDied(enemyId)`, `InteractionCompleted(objectId)`, `CutsceneCompleted(sceneId)`, `ObjectiveCompleted(objectiveId)`, `CheckpointReached(checkpointId)`. 완료 이벤트는 한 번만 반영되며 재로드 시 중복 실행을 막는다.

## 5. MVP 합격 게이트

아래 항목을 모두 통과한 빌드만 MVP로 표시한다. 임시 에셋 사용은 가능하지만 플레이 흐름은 생략하지 않는다.

- 새 게임→추락→소총 확보→회복 학습→Stalker 3마리→집결지 완료.
- 소총·권총 사격, 탄약 소진·재장전·보급·무기 전환이 동작한다.
- Stalker가 시야·소리로 감지하고, 예고 후 공격하고, 죽으면 한 번만 집계된다.
- 사망→체크포인트 재시작 및 앱 종료→이어하기를 모두 확인한다.
- 컷신 전부 건너뛰기·동일 트리거 반복 진입으로 진행이 깨지지 않는다.
- 회복약이 없거나 탄약을 모두 낭비해도 재시작 수단이 있으며 비상 보급이 한 번만 지급된다.
- 이동 불능·카메라 벽 관통·목표 무한 반복·저장 덮어쓰기 손상·충돌 종료 등 진행 차단 문제가 없다.
- 기준 PC·빌드·옵션·플레이 시간·성능 결과·알려진 제한이 기록된다. 아직 측정하지 않은 값은 ‘미측정’으로 표기한다.

## 7. 일정은 인력·엔진 확인 뒤 확정

다음은 플레이 가능한 기존 기반이 있고 전담 구현자 1명과 일부 아트 지원이 있다는 가정의 **작업 분할 예시**다. 실제 납기 추정이나 확정 약속이 아니다. 엔진 경험·가용 시간·외부 에셋에 따라 달라진다.

| 구간 | 예시 기간 | 종료 산출물 |
|---|---|---|
| 조사·기술 스파이크 | 2~3작업일 | 현황표·실행 방법·리스크 |
| P0 기반·CH01 | 10~15작업일 | MVP 빌드·검증 기록 |
| CH02~03·중형 보스 | 15~25작업일 | 플레이 가능한 중반부 |
| CH04~05·엔딩 | 20~30작업일 | 전체 캠페인 알파 |
| 아트 통합·최적화·QA | 15~25작업일 | 배포 후보·권리 목록 |

각 구간 끝에서 실제 진척과 문제를 보고 다음 구간을 재추정한다. 일정이 부족하면 컷신의 촬영 수·선택 기록·배경 모듈 변형·보스 재등장을 줄인다. 5챕터의 고정 사건, 공격 예고, 저장, 최종 성공·실패 조건은 삭제하지 않는다.

## 8. 데이터·콘텐츠 관리

- 플레이어·무기·적·보급·자막·미션은 가능한 한 수정 가능한 데이터로 분리한다.
- 레벨 ID·목표 ID·적 ID·보급 ID의 중복을 검증한다. 표시 이름 변경이 저장 데이터를 깨뜨리면 안 된다.
- 수치 변경 시 [05_GAMEPLAY.md](05_GAMEPLAY.md)를 갱신하고 레벨 탄약 예산을 다시 확인한다.
- 원작 반전·동료 운명 변경은 [02_STORY.md](02_STORY.md)와 캐릭터·레벨 문서를 함께 갱신한다.
- 에셋 승인 상태·라이선스·출처를 [06_ART_DIRECTION.md](06_ART_DIRECTION.md)의 매니페스트 규칙대로 기록한다.
- 엔진 종속 시스템에는 최소 버전과 실행 방법을 적는다. 의존성 추가는 필요한 이유와 라이선스를 확인한다.

## 9. 검증 전략

### 의미 있는 자동 검증

피해 배율·단계 잠금, 탄약 보존·재장전 취소, 회복 취소, 중복 이벤트 억제, 저장 직렬화·버전 오류, 미션 ID 연결을 작은 테스트로 검증한다. 함수 이름이나 파일 존재만 검사하는 테스트를 완료 근거로 삼지 않는다.

### 수동 플레이 검증

| 묶음 | 최소 시나리오 | 기록 |
|---|---|---|
| 시작·조작 | 새 게임, 설정 변경, 조준·회피·점프 | 빌드·입력·발견 문제 |
| 전투 | 전 적 공격 예고·약점·장갑·벽 차폐 | 피해 수치·재현 절차 |
| 미션 | 필수 목표 순서, 순서 무관 목표, 트리거 재진입 | 목표 ID·예상/실제 |
| 저장 | 각 체크포인트 저장→종료→로드 | 체력·탄약·목표·인물 상태 비교 |
| 연출 | 전부 재생, 전부 건너뛰기, 일시정지 | 입력 복구·플래그 확인 |
| 최종전 | 승리, 시간 초과, 노드2개 후 사망 | 420초·노드 초기화·엔딩 1회 |
| 화면 | 720p·1080p·16:10, 흔들림 0, 자막 확대 | 잘림·가독성 |
| 지속 플레이 | 캠페인 연속 플레이·각 챕터 재시작 | 메모리·오디오·이펙트 누적 |

성능은 기준 PC의 CPU·GPU·RAM·OS·드라이버·해상도·그래픽 옵션·빌드를 함께 기록한다. 1080p 보통 설정, 대표 전투 60초 구간에서 평균 60fps 이상·1% low 45fps 이상을 목표로 한다. 로딩은 전투 프레임 집계에서 분리해 기록한다. 실제 하드웨어가 없으면 목표와 측정 불가 사실을 명시한다.

## 11. 캠페인 최종 합격 게이트

1. 프롤로그→5챕터→최종 타격→3개월 후→변이 JIM까지 한 빌드에서 연결된다.
2. 각 챕터를 이어하기와 챕터 시작 기능으로 진입할 수 있다. 챕터 재시작은 해금 장비와 해당 시작 보급을 사용하며 본편 진행 저장을 덮기 전 명확히 안내한다.
3. 주요 반전 4개(고대 귀환·인간 조직의 신호와 과거 참사·선발대·변이)와 마커스 희생이 누락되지 않는다.
4. 모든 보스의 예고·방어·약점·피해·사망/완료 이벤트가 검증된다.
5. 필수 목표 물체 누락, 동료 정체, 탄약 소진, 중복 이벤트로 캠페인이 영구히 막히지 않는다.
6. 알려진 충돌 종료·저장 손상·진행 불능 문제는 0건이어야 한다. 낮은 우선순위 결함은 재현·영향·회피 방법을 기록한다.
7. 기준 PC 성능을 측정하고 목표 미달 구간을 해결하거나 출시 제한으로 명시한다.
8. 최종 사용 에셋·글꼴·음원의 배포 권리가 기록되고 필수 표시가 반영된다.
9. 실행 방법·조작·저장 위치·빌드 버전·알려진 문제·검증 날짜가 함께 제공된다.
